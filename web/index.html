9件别家做不到或不愿做的事
01 数据真的不出本机 不是「我们承诺」，是架构上做不到上传
所有解析在浏览器里跑，没有一个网络请求会带上你的 PDF。 同类工具要么传服务器，要么要 API key；这个断网也能用。 翻译走本机 Ollama 模型，请求地址是 127.0.0.1，出门都出不去。
02 零 API key、零配置 开箱即用，不是「填个 key 就能用」
不注册、不要 key、不装后端。拖进去就出 14 个板块。 翻译功能需要本机 Ollama，但装不装都不影响其他 13 个板块， 没装会明说「没装」，不会假装成功。
03 中文 PDF 的版式问题专门处理过 多数工具在这里翻车
知网导出的 PDF（CNKI ReaderEx）常把左右栏塞进同一行、文字层是碎片。 这里先按坐标重排，再用「行跨度中位数 < 页宽 8%」判断版式可不可信， 不可信才转 OCR——正常论文 1 秒出结果，不白等。 实测：arxiv 英文 1.1 秒 / 37874 字，中文期刊 0.3 秒 / 53045 字， 扫描件 37 秒 / 4416 字且数字全对。
04 判定依据是实测出来的，不是拍脑袋 每个判据都有精确率
句子分类用的规则，精确率来自自家 3611 篇论文 / 110510 句的统计： however 命中 4622 句精确率 100%、we propose 命中 4806 句 96%。 带数字的句子零误伤（13 条全部保留）。这些数字在 README 里可查。
05 空文字层会自动转 OCR 别家在这一步就放弃
很多工具判断「文字层好不好」只看字符有没有乱码，整份是图片这种最坏情况反而算「正常」， 最后报一句「抽不出文字」了事。这里把「一个字都没有」单独当成一条判据， 自动改读页面图片。
实测：WPS 导出的纯图 PDF（文字层 0 字符）→ 41 秒出 5 个板块、6018 字
06 英文 OCR 丢空格的问题专门修过 这一步多数工具没做
引擎读英文图片时常把词间空格丢掉，出来是 TheAIerais"precipitatingapivotal —— 字都认对了， 但切句、提核心句、翻译全废。这里用英文词频表做二次切分， 并把 AI / API / LLM 这类缩写列为保护词不拆。
06.5 OCR 逐字准确，但空格偶尔还会出错 这一条是自曝
词频表不是万能的。实测一页英文扫描件，出来是这样几处： parallel iz able（一个词被拆成三段）、 task,improving（逗号后缺空格）、 thebest（两词粘连）。
字都认对了，是空格没放对。不影响看懂大意， 但拿去引用原文时请对照 PDF 核对一遍。
不藏这事，是因为知道边界在哪才算做过。
07 每一类错误都说清「你该做什么」
不拿一句「图片型 PDF」搪塞所有情况。八种原因分别给话： OCR 认字太少（分辨率低）· 语言包没下下来（网络）· 文件损坏（重新导出）· 文件太大（内存不够）· 文字层只有零星几个字（混合型 PDF）…… 判断不出来时直接说「没判断出来」，并告诉你文件多大几页。
09 翻译走本机模型：不填 key、不注册、断网也能用
译文在这台电脑上算出来，请求地址是 127.0.0.1，字都不出这台电脑。
没有账号、没有额度、没有月费，模型装一次就一直用。
实测：qwen2.5:3b 平均 6 秒一句，术语和数字都对；一篇论文约 30 分钟
08 加密 PDF 能输密码，不是一句英文报错
有些工具遇到加密文件甩一句 No password given 就完了。 这里弹中文密码框，输错告诉你密码不对，输对直接出看板 —— 密码只在本机用，不上传。
